# 包装管理改造需求

状态：已归档（暂缓实施，2026-10-17）
日期：2026-10-15
范围模块：设置 → 产品资料 → 包装预设（改名「包装管理」）；产品库 → 编辑产品 → 包装方式

## 一、背景

现在设置页的「产品预包装预设」只管一件事：往产品编辑器的「包装方式」上方塞一排一键填入的卡片，填的是「包装名称 + 内盒尺寸 + 外箱尺寸 + 装箱数 + 包装采购价」五件套。

两个不顺手的地方：

1. **名字名不副实**。叫「预设」，实际是「一套可维护的包装规格清单」，后续要在里维护更多信息，「预设」两个字框住了可能性。
2. **没有「这套包装能给谁用」的信息**。同样是牛皮纸盒-20台装，电钻能用、扳手不一定能装；现在维护清单时看不出适用范围，产品编辑器里也只有一排平铺的卡片，不给任何提示。

## 二、目标

把「产品预包装预设」改造成「包装管理」，成为包装信息的唯一维护入口：

- 改名「包装管理」，职责从「一键填入模板」升级为「包装规格主数据」。
- 每条包装维护：包装名称、内盒尺寸、外箱尺寸、装箱数、包装采购价（现有五项），**新增「可以装哪些产品」**。
- 「可以装哪些产品」**按产品分类关联**（如「电钻」「扳手」），一条包装可关联多个分类。
- **双向体现**：设置页维护适用范围；产品编辑器里，当前产品分类命中的包装排在预设卡片最前面并带标注，未命中的照常显示在后面。

## 三、范围

**做：**

- 设置页菜单项与区块标题「包装预设」→「包装管理」。
- 包装数据结构新增 `categories: string[]`（适用产品分类，空数组 = 通用，不限定分类）。
- 设置页表格新增一列「可以装哪些产品」：多选分类，用产品库现存的分类做候选（含手动输入新增）。
- 产品编辑器「包装方式」上方的预设卡片：命中的排前 + 角标「适用本类」；未命中的保持原样。
- 「从产品库重新统计」时，按统计出的每条包装反查它被哪些产品用过，把这些产品的分类写进 `categories`（现有统计逻辑不动，只补一个来源）。
- 服务端 API 与共享层的归一化逻辑同步扩展，旧数据（没有 categories 字段）按「通用」处理，不报错。

**不做：**

- 不做「包装方案」的多行组合 packaging（那是产品自己身上的 `packaging` 字段，属于产品数据，不是这里的全局主数据）。
- 不做按具体产品逐一勾选的粒度。
- 不改产品编辑器里包装表格本身的结构与字段。
- 不搬动、不清空现有的预设数据；只做字段扩展，存量 12 条以内继续可用。

## 四、数据与接口

### R1 数据模型

共享类型 `PackagingPreset`（`src/shared/packaging-presets.ts`）扩展：

```ts
export interface PackagingPreset {
  id: string;
  name: string;
  innerSize: string;
  outerSize: string;
  packSize: number;
  purchasePrice: string;
  /** 适用产品分类；空数组 = 通用，不限分类。 */
  categories: string[];
}
```

归一化规则（`normalizePackagingPreset`）：

- `categories` 缺省 → `[]`（旧数据无缝升级）；
- 只保留非空字符串，去重，按写入顺序；单项长度上限 30，总数上限 12；
- **有效性判定包含 categories**：只勾了分类、规格还没填的行是维护中的中间状态，丢掉它会让用户以为保存成功、实际内容消失，所以有分类就算有效；名称与四个规格字段连同 categories 全空才视为无效行。

接口 `GET/PUT /api/settings/packaging-presets` 的出入参结构不变（整份数组覆盖保存），字段多一个 `categories`。

### R2 分类候选来源

新增 `GET /api/settings/packaging-categories`（或并入现有产品分类接口）：返回产品库里出现过的全部分类名称及产品数，供设置页的多选框做候选。候选要包含「现存分类 + 用户手工输入的新分类」。

### R3 重新统计补分类

`reseedPackagingPresets` 的统计源从「包装行」扩展为「包装行 + 所属产品的分类」：每条统计出的包装，取其来源产品分类的去重集合写入 `categories`。统计不到分类（例如历史产品没填分类）的保持 `[]`。

### R4 产品编辑器匹配

`PackagingTable` 接收一个 `activeCategories: string[]`（当前产品分类，可能是多个标签），排序规则：

- 命中（`preset.categories` 为空，或与 `activeCategories` 有交集）→ 排在前半，卡片带「适用本类」角标；
- 未命中 → 排在后半，无角标；
- 组内保持用户原有顺序（上移/下移的相对位置不动）。

## 五、验收

1. 设置页菜单、区块标题、界面文案都显示「包装管理」，不再出现「预设」字样（代码内部标识符可保留 `packaging-presets`，避免无谓的接口迁移）。
2. 新增一条包装，填好五项 + 勾选「电钻」，保存后刷新页面仍在。
3. 产品编辑器里编辑一个分类为「电钻」的产品：预设卡片第一张就是刚建的那条，带「适用本类」；编辑一个分类为「扳手」的产品：同一条排在后面且无角标。
4. 旧数据升级：不填 `categories` 的老预设在产品编辑器里照常显示、按「通用」参与命中。
5. 「从产品库重新统计」跑完后，新统计出的包装带上了来源产品分类。
6. 编译与测试：`npm run typecheck` 通过，`tests/unit/packaging-presets.test.ts` 与相关服务端测试通过；新增用例覆盖 categories 归一化（缺省、去重、超限截断、不参与空行判定）与编辑器命中排序。

## 六、风险

- **接口字段扩展是向后兼容的**（旧客户端不传 `categories`，服务端归一化补 `[]`），但前后端必须同批上线，否则旧前端存一次会把 categories 清空 —— 本次改动就是前后端一起部署，不涉及灰度窗口。
- 分类匹配是**字符串精确匹配**：产品分类名写「电钻」而包装关联写「电钻 」（带空格）会不命中。前后端都对分类名做 trim，且候选来自产品库现存分类，正常不会漂移。
