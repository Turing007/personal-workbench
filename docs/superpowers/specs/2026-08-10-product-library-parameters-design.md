# 产品库参数列设计规格

## 1. 背景与目标

产品库当前已经支持产品基本信息、包装方式、颜色、电池插脚、供应商、采购价和多图片维护。为便于在产品列表中快速识别同品名不同规格的产品，并在报价单、订单中复用完整的产品信息，需要增加“参数”字段。

本次变更的目标是：

- 在产品编辑器中增加可自由填写的多行“参数”字段；
- 在产品列表中加入“参数”列，并按照确认的顺序展示产品信息；
- 点击 SKU 可以查看包含完整参数的产品详情；
- 保留点击图片查看全部图片、选择图片和复制图片的能力；
- 产品被报价单或订单调用时同步携带参数；
- 兼容已有产品数据，不要求用户迁移或重新录入旧产品。

本次不新增参数名和值的结构化表格、不做参数级筛选、不改变 SKU 自动生成规则、不重构报价单和订单的其他业务流程。

## 2. 已确认的用户体验

### 2.1 产品列表

产品列表列顺序固定为：

**SKU → 图片 → 品名 → 规格 → 参数 → 包装信息 → 颜色 → 插脚 → 供应商 → 价格**

约束：

- SKU 是产品行的主要识别入口，使用可点击文本或等价的可访问按钮打开详情弹窗；
- 图片列展示缩略图或图片数量入口。没有图片时显示占位状态；
- 参数列显示多行文本的前 1～2 行，保留换行语义，超出列表可用省略号收起，避免撑高表格；
- 颜色和插脚仍按已确认的多选数组显示，多个值使用“、”连接；
- 包装信息仍按每种包装方式一行维护，并在列表中以紧凑文本汇总；
- 价格显示采购价，没有价格时显示“未设置”或等价的空状态；
- 继续使用现有搜索能力，品名、SKU、规格仍可筛选，参数暂不作为筛选条件，避免把列表搜索语义扩大到本次范围之外；
- 列表保持紧凑布局，长参数不得造成页面整体出现无意义的纵向空白。

### 2.2 产品编辑器

在品名、SKU、规格、采购价等基础信息区域中增加“参数”多行文本框。参数字段为可选字段，建议展示 4～6 行输入高度；每行填写一项，推荐格式为“参数名：参数值”，例如：

```text
扭矩：35N·m
转速：0-1500rpm
额定电压：12V
电池容量：4.0Ah
```

行为约束：

- 保存时保留用户输入的换行和文字内容，不自动拆分、排序或改写；
- 输入为空时保存为空字符串；
- 编辑已有产品时回填完整参数；
- 清空编辑器时参数一并清空；
- 必须兼容 SKU 由系统自动生成的现有流程，SKU 仍不可手动编辑；
- 不因为参数为空阻止保存产品。

### 2.3 SKU 详情弹窗

点击 SKU 打开现有产品详情弹窗或补充现有详情弹窗，弹窗中展示：

- SKU、品名、规格；
- 完整参数（保留换行）；
- 包装信息；
- 颜色、电池插脚、供应商、采购价；
- 产品图片入口或缩略图入口。

详情弹窗是只读查看入口；编辑仍通过现有产品编辑操作完成。参数为空时显示“暂无参数”，而不是留出大块空白。

### 2.4 图片弹窗

保留现有图片交互：

- 点击列表中的图片或图片数量入口，打开该产品的图片弹窗；
- 弹窗展示产品的全部图片缩略图和当前选中图片；
- 支持选择一张图片；
- 点击“复制所选图片”将当前图片复制到剪贴板，并反馈成功或失败；
- 没有图片时显示明确的空状态；
- 复制失败时提示浏览器权限或当前环境不支持，不影响产品数据。

## 3. 数据模型与兼容策略

### 3.1 产品字段

在 `products` 表增加：

```sql
parameters TEXT NOT NULL DEFAULT ''
```

使用单个 TEXT 字段保存完整多行文本，不另建参数明细表。这样与用户选择的 A 方案一致，也能保持参数的原始排版。

前端 `ProductRecord` 增加：

```ts
parameters: string;
```

产品 API 的读取、创建、更新响应和请求体均使用同一语义字段 `parameters`。后端对其做可选文本归一化：未传、`null` 或空值均按空字符串处理；非字符串值返回校验错误，不隐式转换对象或数组。

### 3.2 数据库迁移

- 新安装数据库在建表 SQL 中直接创建 `parameters` 字段；
- 已有数据库通过幂等迁移增加字段，例如先检查 `PRAGMA table_info(products)`，不存在时执行 `ALTER TABLE products ADD COLUMN parameters TEXT NOT NULL DEFAULT ''`；
- 迁移不删除、重建或覆盖 `data/`，不改变现有产品、图片、包装和 SKU 序号；
- 迁移重复执行必须安全；
- 旧产品的参数默认为空字符串，读取和编辑均可正常工作。

### 3.3 跨模块携带

- 报价单从系统产品库选择产品时，将参数复制到报价单明细的产品快照中；
- 订单从系统产品库选择产品时，将参数复制到订单明细的产品快照中；
- 产品后续修改不回写已经保存的报价单或订单快照，避免历史单据内容随产品库变化；
- 本次只要求数据可被调用和保留，不要求报价单或箱唛默认打印参数。已有单据展示规则保持不变，除非对应模块已经存在产品参数展示入口。

## 4. 组件与接口边界

### 4.1 前端

- `ProductEditor`：负责参数文本框的受控输入、回填和提交；
- `ProductsPage`：负责参数列、SKU 详情入口、图片入口及空状态/截断展示；
- 产品详情弹窗：只负责读取并展示 `ProductRecord`，不修改数据；
- 图片弹窗：只负责图片选择、预览和复制反馈；
- `api.ts`：负责 API 类型映射以及 `productToInput` / `mapProductRecord` 的参数传递；
- 订单/报价单产品选择器：在选择系统产品时把参数写入各自的明细快照类型和提交映射。

### 4.2 后端

- `products` 路由：校验和映射 `parameters`；
- 数据仓库：读写 `products.parameters`，列表返回该字段；
- 数据库迁移：为新旧数据库提供幂等字段升级；
- 报价单、订单相关仓储和路由：接收并保存调用时的参数快照，不改变其既有状态流转。

各层不得通过 `JSON.stringify` 把参数数组伪装成文本字段，也不得在 UI 层重复实现后端字段转换。

## 5. 业务流程

1. 用户在产品编辑器中填写基本信息和多行参数并保存。
2. 前端提交 `parameters`，后端校验后保存到产品记录。
3. 产品列表按确认顺序显示参数摘要。
4. 用户点击 SKU 查看完整产品信息和完整参数。
5. 用户点击图片查看全部图片，选择图片并复制；图片复制失败时只提示，不回滚产品保存。
6. 用户在报价单或订单中按品名、SKU、规格调用产品，产品参数随调用写入当前单据明细快照。
7. 用户之后修改产品库参数时，历史报价单和订单仍保持原参数内容。

## 6. 校验、错误处理与边界情况

- 参数不是必填字段；
- 参数仅接受字符串，保留前后空格和换行的显示内容，但可在服务端保存前对整个字段做安全的空值处理；
- 超长文本应由现有请求体限制或数据库自然支持，若命中请求体限制，沿用统一 API 错误提示，不静默截断；
- 产品列表中参数为空显示“—”；
- 参数仅有一行时完整显示，不显示多余省略号；
- 参数有多行或超出单元格展示空间时仅截断列表摘要，详情弹窗必须展示完整内容；
- 旧 API 响应没有 `parameters` 时前端按空字符串兼容；
- 复制图片要求使用 `navigator.clipboard` 或现有兼容方案，权限拒绝时展示可理解的失败提示；
- 产品保存失败时保持编辑器打开并保留草稿，沿用现有错误处理；
- 数据库迁移失败时服务启动失败并记录明确错误，不执行破坏性回滚。

## 7. 测试策略

### 7.1 后端单元/集成测试

- 新建产品可保存并读取多行参数；
- 编辑产品可覆盖参数，空参数可保存；
- 缺少参数字段时接口仍兼容并返回空字符串；
- 参数为非字符串时返回校验错误；
- 旧数据库执行迁移后拥有 `parameters` 字段，原有产品和 SKU 序号不变；
- 产品列表 API 返回 `parameters`；
- 报价单和订单调用产品时保存参数快照，之后产品库修改不会改变历史快照；
- 现有产品测试、订单测试、报价单测试和迁移测试全部继续通过。

### 7.2 前端验证

- 新建、编辑、清空产品时参数字段行为正确；
- 列表列顺序和参数摘要布局正确；
- SKU 详情弹窗显示完整参数并正确处理空参数；
- 图片弹窗能展示全部图片、选择图片并反馈复制结果；
- 窄屏下列表可横向查看，编辑器和弹窗不发生内容重叠；
- `npm run typecheck`、`npm test`、`npm run build` 和 `git diff --check` 通过。

## 8. 实施范围与验收标准

### 本次实施包含

- 产品库参数字段的数据库、后端 API、前端类型和编辑 UI；
- 产品列表的参数列及其展示顺序；
- SKU 详情弹窗和图片选择/复制交互；
- 报价单和订单调用产品时的参数快照传递；
- 对应测试和兼容迁移。

### 本次实施不包含

- 参数名和值结构化管理；
- 参数独立筛选、排序或批量编辑；
- 参数自动解析、单位换算或规格校验；
- 箱唛默认显示参数；
- 与本需求无关的页面重构或数据库清理。

### 验收标准

用户可以在产品编辑器中输入多行参数并保存；列表按确认顺序看到参数列；点击 SKU 能看到完整参数；图片仍可查看、选择和复制；从产品库调用到报价单或订单的参数会被保留；已有数据正常打开，测试和构建均通过。
