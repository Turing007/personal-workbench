# 按客户分类的客户产品库改造规格

**状态：** 用户已确认
**日期：** 2026-08-11

## 1. 目标与范围

将现有客户产品库改造成按客户独立维护的产品目录，使报价单可以把客户报价结果同步到客户产品库，之后销售开单和新建订单可以按客户调用对应产品、SKU、装箱数和最终价格。

本次改造包含：

1. 建立独立客户档案和客户产品关联关系。
2. 报价单选择客户，并支持默认全选、可取消部分产品后同步。
3. 客户产品库采用左侧客户列表、右侧产品表的 A 布局。
4. 报价单、销售开单、新建订单按客户调用产品。
5. 增加数据迁移、重复识别、历史快照、异常保护和验收测试。

本次不改变箱唛、打印、备货、发货等既有功能的业务规则；这些功能只消费本次新增的客户和产品快照数据。保留工作区现有未提交改动，不删除 `data/` 目录，不删除历史报价单、销售开单或订单。

## 2. 数据模型

### 2.1 客户档案

新增客户主表，使用稳定的内部客户 ID，不使用客户名称作为外键。

字段：

| 字段 | 规则 |
| --- | --- |
| 客户 ID | 系统生成，创建后保持不变 |
| 客户名称 | 必填；用于显示和搜索 |
| 联系人 | 可选 |
| 联系电话 | 可选 |
| 常用收件信息 | 可选多行文本，保存常用收件人、地址、电话等信息 |
| 状态 | 启用或停用；停用客户不可用于新建单据，但历史单据仍可查看 |
| 创建时间、更新时间 | 系统维护 |

新增客户时，如果名称相同，提示已有同名客户；用户确认后仍允许建立独立客户档案，以支持同名但实际不同的客户。

### 2.2 客户产品

新增或改造客户产品关联表，每条记录属于一个客户，并可选关联一个系统产品。

字段：

| 字段 | 规则 |
| --- | --- |
| 客户产品 ID | 系统生成 |
| 客户 ID | 必填，关联客户档案 |
| 系统产品 ID | 可为空；临时产品没有系统产品关联 |
| 品名 | 必填 |
| 规格 | 可为空；参与临时产品查重 |
| 客户 SKU | 可为空；由报价同步生成或人工维护 |
| 装箱数 | 可为空；由报价同步生成或人工维护 |
| 最近报价 | 可为空；报价同步时更新 |
| 最终价格 | 可为空；人工维护的成交价格 |
| 完善状态 | 自动计算为“待完善”或“已完善” |
| 来源报价单 ID | 可为空；记录最近一次同步来源 |
| 最近同步时间 | 可为空 |
| 创建时间、更新时间 | 系统维护 |

完善状态规则：最终价格、客户 SKU、装箱数任意一项为空时为“待完善”；三项全部有值时为“已完善”。装箱数如果存在则必须为正整数。

重复产品识别规则：

- 已关联系统产品的客户产品，按“客户 ID + 系统产品 ID”唯一识别。
- 未关联系统产品的临时产品，按“客户 ID + 品名 + 规格”识别。
- 同品名不同规格视为不同产品，不合并。
- 同一客户同一识别键只保留一条客户产品记录。

### 2.3 单据关联与快照

报价单、销售开单、新建订单均增加 `customerId`。选择客户后自动带入客户资料，但单据中的临时修改不覆盖客户档案。

每张已保存单据同时保存当时的客户资料和产品信息快照，包括品名、规格、SKU、装箱数、单价及必要的系统产品关联信息。以后修改客户档案或客户产品，不影响历史单据的展示、金额和业务记录。

新建订单继续保留原有客户来源字段。客户档案和客户来源是两个独立概念：客户用于关联客户产品，客户来源用于记录订单从微信、1688 等渠道或来源名称进入系统。

## 3. 报价单同步流程

### 3.1 报价单客户

报价单新建和编辑时支持搜索已有客户，也支持快速新增客户。选择客户后带入联系人、联系电话和常用收件信息；报价单中临时修改只作用于当前报价单。

未选择客户的报价单可以保存，但不能执行“同步到客户产品库”，点击同步时引导用户先选择或新增客户。

### 3.2 同步弹窗

报价单保存后显示“同步到客户产品库”按钮。点击后打开同步弹窗：

- 报价单产品默认全部勾选。
- 用户可以取消任意产品，再确认同步。
- 每行显示产品图片、品名、规格、本次报价和同步结果预判。
- 预判结果包括新增、更新最近报价和无变化。

### 3.3 同步规则

确认同步后：

1. 新产品生成一条对应客户的客户产品记录。
2. 已存在产品只更新最近报价、来源报价单 ID 和同步时间。
3. 最终价格、客户 SKU、装箱数不被重复同步覆盖，保留人工维护值。
4. 报价单中的临时产品可以同步，但不关联系统产品库。
5. 新记录缺少最终价格、客户 SKU 或装箱数时标记为“待完善”。
6. 同步使用事务处理；单行失败不回滚已成功的行，并返回每行成功或失败原因。
7. 重复点击同步不会重复创建产品，也不会把最近报价以外的人工维护字段覆盖掉。

同步完成后显示新增数量、更新数量和失败数量，并提供进入当前客户产品库、筛选“待完善”的入口。报价单保存同步时间，便于追溯来源。

## 4. 客户产品库界面

页面采用已确认的 **A 布局：左侧客户列表 + 右侧客户产品表**。

### 4.1 左侧客户列表

- 支持按客户名称、联系人和电话搜索。
- 每个客户项显示客户名称、产品总数和待完善数量。
- 顶部提供新增客户按钮。
- 客户资料通过紧凑弹窗新增或编辑。
- 默认优先显示存在待完善产品的客户，便于报价后集中补齐信息。
- 已停用客户可查看历史内容，但不能用于新增报价单、销售开单或订单。

### 4.2 右侧产品区

选择客户后，右侧只显示当前客户的产品，顶部显示客户名称及联系人摘要。

提供以下筛选和操作：

- 状态筛选：全部、待完善、已完善。
- 产品搜索：品名、客户 SKU、规格。
- 新增客户产品。
- 从系统产品库调用。
- 批量删除。

产品表格列为：状态、图片、品名、规格、SKU、装箱数、最近报价、最终价格、来源、更新时间和操作。

点击产品行或编辑按钮，打开紧凑编辑弹窗，可修改品名、规格、SKU、装箱数和最终价格。关联系统产品时，默认带入系统产品信息，但客户专属字段允许修改。保存后重新计算完善状态。

点击来源报价单可以查看原报价单。删除客户产品需要二次确认，且不影响历史单据。客户已有产品或历史单据时禁止直接删除，只能停用客户。

## 5. 三类单据调用客户产品

报价单、销售开单和新建订单统一使用以下调用流程：

1. 先搜索并选择客户，或快速新增客户。
2. 选择客户后带入联系人、联系电话和常用收件信息。
3. 默认显示当前客户的“已完善”产品。
4. 支持切换查看“待完善产品”。
5. 支持从系统产品库调用产品。
6. 系统产品库和客户产品库都没有匹配时，允许临时添加产品。

产品搜索支持品名、客户 SKU 和规格。调用客户产品时自动带入品名、规格、客户 SKU、装箱数和最终价格。

最终价格为空时显示待完善提示，不自动把最近报价当作成交价。数量、单价、行金额和订单总金额按现有单据规则自动计算，同时允许在当前单据中手动调整。单据内的产品字段、价格或客户资料调整只保存为本单内容，不覆盖客户档案和客户产品。

保存单据前提示缺失的 SKU、装箱数或最终价格，但不强制阻止保存，以支持临时开单。新订单中的客户字段与客户来源字段分开保存。

## 6. 迁移与兼容

迁移新增客户主表、客户产品关联表，并为报价单、销售开单和订单增加客户关联及快照所需字段。

旧客户产品库数据按已确认要求直接清空，再从报价单手动同步生成新数据。历史报价单、销售开单和订单完整保留，不删除、不改金额，不改变原客户来源文本。旧单据中的客户名称只作历史展示；编辑旧单据时允许重新选择或绑定客户档案。

客户来源默认保留“微信”和“1688”，客户来源类型继续支持新增和删除。

迁移必须可重复执行，不因重复启动造成重复表、重复列或重复客户产品记录。启动失败时返回明确错误，不删除现有业务数据。

## 7. 异常保护

- 未选择客户时禁止报价单同步。
- 同名客户新增时提示，但允许确认后继续创建。
- 部分产品同步失败时保留已成功产品，列出失败产品和原因。
- 删除客户产品二次确认，不影响历史单据。
- 已有关联产品或历史单据的客户只能停用。
- 停用系统产品不删除客户产品和历史单据快照。
- 价格、SKU、装箱数允许为空，但必须显示“待完善”。
- 同一客户系统产品或临时产品重复识别时更新原记录，不新建重复数据。

## 8. 测试与验收

至少覆盖以下场景：

1. 新增、编辑、停用客户，三类单据可以调用客户资料。
2. 报价单默认全选，取消部分产品后同步，只有选中产品进入客户产品库。
3. 首次同步生成客户产品，重复同步只更新最近报价。
4. 重复同步不覆盖最终价格、客户 SKU 和装箱数。
5. 系统产品和临时产品按规则正确识别重复关系。
6. 同品名不同规格保持为不同产品。
7. 客户产品完善状态按字段完整性自动切换。
8. 三类单据优先调用已完善产品并带入最终价格。
9. 单据内临时修改不改变客户档案和客户产品库。
10. 历史单据金额、产品信息和客户来源保持不变。
11. 客户切换、产品搜索、状态筛选和待完善筛选正常。
12. 数据库升级后系统可正常启动，`data/` 目录数据不丢失。

## 9. 明确不包含的内容

本规格不新增供应商备货表、不重新设计箱唛模板、不改变发货表格式、不引入客户自动同步或自动修改客户产品的后台任务。客户产品库同步只在用户点击报价单上的同步按钮并确认后执行。
