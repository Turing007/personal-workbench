# 订单增强功能设计规格

**日期：** 2026-08-10  
**状态：** 已获用户确认，等待实现计划审查

## 1. 目标与范围

本次为订单管理模块增加三个相互关联但边界清晰的能力：

1. 新建订单时自动生成销售订单号，并允许用户手动修改；
2. 在订单表单内直接维护客户来源类型；
3. 为订单增加合同附件上传、查看、下载和删除能力。

本次不改变产品库、报价单、销售开单、箱唛编辑/打印、备货、发货状态流转及付款凭证的既有业务规则。合同附件与付款凭证是两类独立数据，不共用前端字段和数据库记录。

## 2. 已确认的业务规则

### 2.1 订单号

- 新建订单默认生成 `SO20260810001` 形式的订单号。
- 格式为 `SO` + 8 位日期 `YYYYMMDD` + 当日 3 位流水号。
- 示例：2026 年 8 月 10 日当天的第 1 个自动订单号为 `SO20260810001`。
- 订单号输入框仍可编辑，用户可以在保存前手动修改。
- 手动修改后的订单号必须非空，并且不能与已有订单重复。
- 编辑已有订单时保留原订单号，不因打开编辑窗口或修改下单时间而重新生成。
- 订单号的自动生成以服务端为准，避免多浏览器窗口或重复点击导致重复号码。

### 2.2 客户来源类型

- 默认启用的来源类型只有：`微信`、`1688`。
- 新建/编辑订单表单的客户来源类型下拉框旁放置“添加”和“删除”操作。
- 添加来源时输入名称，名称去除首尾空格后保存；同名来源不允许重复。
- 新增成功后立即加入当前表单的可选项，并可直接选中。
- 删除未被历史订单使用的来源时可以直接删除配置记录。
- 删除已经被历史订单使用的来源时不删除历史文本，而是将来源类型停用：
  - 停用来源不再出现在新订单的默认下拉选项中；
  - 历史订单仍显示原来的来源文本；
  - 编辑历史订单时，为保证表单可回显，当前已停用来源作为临时只读选项保留，用户保存后仍可改选为启用来源。
- 删除操作需要确认，避免误删。
- 来源类型的配置名称不影响订单表中的 `source_type` 文本快照，因此历史订单不会因为配置变更而失真。

### 2.3 合同附件

- 一个订单允许上传多份合同。
- 支持以下文件：
  - PDF：`.pdf`；
  - Word：`.doc`、`.docx`；
  - Excel：`.xls`、`.xlsx`；
  - 图片：PNG、JPEG、WebP。
- 新建订单时可以先选择多个合同文件；订单保存成功后，系统自动将这些文件上传并绑定到新订单。
- 编辑订单时可以继续添加合同，也可以删除已有合同。
- 订单详情中显示合同文件名、文件类型、文件大小和上传时间，并提供查看/下载、删除操作。
- 合同文件不显示在付款凭证区域，也不使用付款凭证备注字段。
- 合同文件保存到 `data/files/order-contracts/`，通过订单 ID 关联。
- 合同附件纳入现有备份和恢复流程。

## 3. 交互设计

### 3.1 新建订单表单

订单号字段的行为：

1. 打开“新建订单”弹窗时请求服务端生成一个当前日期的预览订单号；
2. 预览订单号直接填入输入框，例如 `SO20260810001`；
3. 用户不修改时，保存请求可以将其作为自动订单号提交，服务端在事务中再次生成最终号码；
4. 用户修改过输入框时，保存用户输入的订单号；
5. 服务端返回最终订单号后，列表和成功提示使用最终值。

如果预览请求失败，表单仍可打开，订单号输入框保持可编辑；保存时提交空订单号即可让服务端生成，或提交用户手动输入的值。

客户来源字段使用“下拉框 + 添加按钮 + 删除按钮”的紧凑布局：

- 添加：弹出一个小型输入对话框或内联输入区，提交后刷新来源列表并选中新来源；
- 删除：删除当前选中的来源，先显示确认提示；没有选中来源或当前值为空时不执行；
- 如果来源已被历史订单使用，提示“该来源已被历史订单使用，将停用而不是删除”。

合同区域放在订单基础信息区域，与付款凭证分开：

- “选择合同”按钮使用 `multiple` 文件选择；
- 文件选择后先显示本地待上传列表，包含文件名和大小；
- 新订单保存前可以移除待上传文件，不产生服务器文件；
- 编辑已有订单时，已保存合同与待上传合同分组显示；
- 移除已有合同只在点击“保存订单”后提交删除，取消编辑不会删除服务器文件；
- 文件类型不支持时在表单中显示明确错误，不影响用户继续编辑其它字段。

### 3.2 订单详情

订单详情弹窗新增“合同附件”区域：

- 无合同：显示“暂无合同附件”；
- 有合同：按上传时间倒序列出文件；
- “查看/下载”使用附件 URL，并保留原始文件名作为下载名；
- “删除”要求确认，删除成功后刷新当前订单详情；
- 付款凭证区域保持现有的图片预览、备注和删除逻辑。

### 3.3 来源类型历史回显

订单表的 `source_type` 继续存储文本快照，不改成外键。编辑订单时如果快照对应的配置已经停用，前端将该值临时加入选择项并标记“已停用”，保存到另一来源后不再回显该临时项。

## 4. 数据模型

### 4.1 客户来源配置表

新增表 `order_source_types`：

```sql
CREATE TABLE order_source_types (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  is_active INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0, 1)),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

迁移策略：

- 首次迁移时插入启用的 `微信`、`1688`，使用幂等写入；
- 对现有 `orders.source_type` 中非空且尚未进入配置表的值建立停用配置记录，使历史订单来源可识别但不会污染默认新订单选项；
- 不修改现有订单的 `source_type` 文本。

### 4.2 订单合同表

新增表 `order_contracts`：

```sql
CREATE TABLE order_contracts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  order_id INTEGER NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
  relative_path TEXT NOT NULL UNIQUE,
  original_name TEXT NOT NULL,
  mime_type TEXT NOT NULL,
  size_bytes INTEGER NOT NULL CHECK (size_bytes >= 0),
  created_at TEXT NOT NULL
);
```

新增索引：

```sql
CREATE INDEX idx_order_contracts_order
  ON order_contracts(order_id, created_at DESC, id DESC);
```

### 4.3 订单号流水表

新增表 `order_number_sequences`：

```sql
CREATE TABLE order_number_sequences (
  sequence_date TEXT PRIMARY KEY,
  last_value INTEGER NOT NULL CHECK (last_value > 0)
);
```

服务端在创建自动订单号时在同一事务中锁定并递增当天记录；流水号至少为 1，格式化时左侧补零到 3 位，超过 999 后自然扩展为 4 位或更多位，不截断也不覆盖已有订单。

## 5. 服务端架构与接口

### 5.1 文件存储扩展

扩展 `src/server/files/file-store.ts`，保留现有图片 API，同时增加通用附件保存能力：

- 新增 `FileKind`：`order-contract`；
- 新增公共目录：`order-contracts`；
- 图片继续按 MIME 类型校验和使用图片大小限制；
- 合同按允许的 MIME 类型和扩展名双重校验；
- 合同使用独立的文件大小限制，默认 20 MB/文件；
- 文件名仍使用安全 basename 处理，实际保存文件名使用 UUID，数据库保留原始文件名。

扩展 `src/server/config.ts`：

- 增加 `orderContractsDirectory`；
- 增加合同允许 MIME 类型和扩展名配置；
- 增加 `maxContractSize`，默认 20 MB。

### 5.2 订单号接口

新增：

```text
GET /api/orders/next-number
```

返回：

```json
{ "number": "SO20260810001", "date": "20260810" }
```

该接口用于表单预览，不提前消耗流水。真正创建订单时由数据库事务生成最终号。

调整订单创建请求：

- `orderNo` 允许为空或省略，表示使用自动编号；
- 非空时视为用户手动编号；
- 更新订单时仍要求已有订单号，不能因为空值意外重置订单号。

订单创建响应返回包含最终订单号的完整订单详情。唯一约束冲突继续转换为 `ORDER_NO_EXISTS`。

### 5.3 客户来源接口

新增：

```text
GET    /api/order-source-types
POST   /api/order-source-types
DELETE /api/order-source-types/:id
```

请求/响应约定：

- GET 默认只返回启用来源；可选 `includeInactive=1` 供编辑历史订单时回显；
- POST body 为 `{ "name": "来源名称" }`，返回新配置；
- DELETE 根据是否存在订单使用记录决定物理删除或停用，并返回 `{ id, name, isActive, mode }`；其中 `mode` 为 `deleted` 或 `deactivated`；
- 名称重复返回 `SOURCE_TYPE_EXISTS`；空名称返回校验错误；
- 删除不存在的配置返回 404。

### 5.4 合同接口

新增：

```text
GET    /api/orders/:id/contracts
POST   /api/orders/:id/contracts
DELETE /api/order-contracts/:id
```

合同上传使用 multipart：

- 字段名为 `file`；
- 一次请求只上传一个文件，前端通过多次请求完成多文件上传；
- 服务端先确认订单存在，再校验文件类型、扩展名和大小；
- 文件保存成功后写入 `order_contracts`；数据库写入失败时删除已保存文件；
- 返回 `id`、`orderId`、`originalName`、`mimeType`、`size`、`createdAt` 和 `/files/order-contracts/<uuid>...` URL。

删除合同时先删除数据库记录，成功后删除物理文件；物理文件已不存在不阻止数据库记录清理。

订单详情返回新增字段：

```ts
contracts: Array<{
  id: number;
  orderId: number;
  relativePath: string;
  originalName: string;
  mimeType: string;
  size: number;
  createdAt: string;
  url: string;
}>;
```

### 5.5 备份恢复

将 `order_source_types`、`order_contracts` 和 `order_number_sequences` 加入 `BackupService` 的表清单。合同目录位于现有 `data/files` 下，因此现有附件清单会自动纳入 `files/order-contracts/...`；恢复时数据库记录与物理附件继续使用清单进行一致性校验。

## 7. 错误处理与安全边界

- 订单号重复：返回 409 和 `ORDER_NO_EXISTS`，前端定位到订单号输入框；
- 来源名称为空或重复：表单内提示，不能提交；
- 删除来源时如果来源已被订单使用，只执行停用，不删除历史文本；
- 合同 MIME 类型或扩展名不允许：返回 415；
- 合同超过 20 MB：返回 413；
- 合同没有文件：返回 400；
- 订单不存在时，合同列表、上传和删除均返回 404；
- 物理文件路径只允许使用 FileStore 生成的两段式相对路径，拒绝绝对路径、`..` 和未知目录；
- 原始文件名只用于展示/下载，不能作为物理存储路径；
- multipart 总文件限制保持现有上限，同时将图片与合同的大小错误分别映射为用户可理解的提示。

## 8. 测试策略

### 8.1 服务端单元/集成测试

- 订单号格式化：指定日期首次生成 `SOYYYYMMDD001`；连续生成递增；超过 999 不截断；
- 自动订单号创建：空 `orderNo` 能创建并返回最终编号；
- 手动订单号创建：自定义编号能保存；重复编号返回 `ORDER_NO_EXISTS`；
- 订单更新：不重新生成订单号；
- 来源迁移：初始化包含微信、1688；已有历史来源被建立为停用配置；
- 来源新增：空名称、重复名称被拒绝，正常名称可新增；
- 来源删除：未使用来源物理删除，已使用来源停用且历史订单仍保留文本；
- 合同上传：支持 PDF、DOC/DOCX、XLS/XLSX、PNG/JPEG/WebP；不支持的类型被拒绝；超限被拒绝；
- 合同持久化：文件记录、订单详情、合同列表字段一致；
- 合同删除：数据库记录和物理文件均清理；
- 备份恢复：合同表和合同文件在备份清单与恢复结果中存在。

### 8.2 前端测试

- 新建表单显示自动订单号，用户修改后保留手动值；
- 动态来源可以添加、选择和删除/停用；
- 历史停用来源可以在编辑订单时正确回显；
- 合同可多选加入待上传列表、移除待上传文件；
- 已保存合同显示文件名、大小、下载和删除操作；
- 付款凭证功能未受合同字段影响。

## 9. 非目标

- 不把订单号改造成报价单或销售单编号；
- 不把客户来源类型改成订单外键，不重写历史订单来源；
- 不把合同解析成结构化商品或金额；
- 不增加合同在线编辑、Office 在线预览、电子签章或版本管理；
- 不改变付款凭证必须为图片、支持 Ctrl+V 粘贴的既有规则；
- 不重构与本需求无关的页面和数据库模块。
