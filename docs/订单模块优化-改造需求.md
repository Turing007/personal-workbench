# 订单模块优化 · 改造需求

## 1. 背景与目标

订单模块现在开单必须先在客户档案里建好客户、再从该客户的产品库选品。遇到临时来单的新客户，就得先走一遍建客户流程；产品明细行也没有图片，核对款式不直观；客户产品库里没有的新品，只能手填或先建客户产品。

本次做四项优化（前三项是原始需求，第四项是确认补充）：

1. **临时客户开单**：系统里没有的客户，直接在订单上输名字就能开单，不必先建客户档案。
2. **产品明细带图**：「填写订单详情」弹窗里的每行产品带上产品图片，点击可放大。
3. **系统产品库直选 + 存入客户产品库**：添加新品时能像客户产品库那样直接从系统产品库选品带入订单；加入订单后，可一键把该行存入客户产品库。
4. **临时客户转正**：临时客户后来成了正式客户，一键转成客户档案，并把该名称的历史订单自动挂接过去。

已确认的取舍：临时客户**只在订单上记名称、不建档案**；转正**要做**；存入客户产品库用**订单行上的按钮、想存再存**。

## 2. 功能一：临时客户开单

### 入口与交互

- 客户选择器（订单表单顶部「客户」）在现有「搜索选择 / 快速新增客户」之外，支持**直接输入一个名字作为临时客户**：
  - 输入的名字与已有客户都不匹配时，下拉里出现一条「按临时客户开单：xxx」，点选即生效。
  - 输入后未选任何已有客户就离开输入框，也按临时客户名称生效（不强制点选）。
  - 生效后输入框显示该名称，并带一个「临时」小标记，区别于正式客户。
- 选临时客户后，订单照常填写产品、数量、单价、收件信息并保存。

### 数据与显示

- 订单保存为 `customer_id = null` + `customer_name = 输入的名称`（后端已支持名称快照，本次主要补前端入口）。
- 订单列表、详情、行内展开、财务等凡是显示客户名的地方，照常显示该名称，并带「临时」标记，方便识别哪些单还没挂正式客户。
- 临时客户**不进入客户列表**，不产生客户档案。

### 约束（重要）

- 客户产品库必须挂在正式客户下（数据库强约束）。**临时客户订单不能从客户产品库选品，也不能存入客户产品库**，只能：
  - 从**系统产品库**直选（功能三），或
  - 手动填写产品行。
- 客户产品选择器在临时客户下显示提示：「临时客户暂不能用客户产品库，可从系统产品库选品；转正后可存入客户产品库。」
- 想用客户产品库，先做转正（功能四）。

## 3. 功能二：产品明细带图

- 范围：**「填写订单详情」弹窗的产品明细行**（订单查看页已有图，保持不动）。
- 每行在品名前加一张缩略图：
  - 来源优先级：客户产品自有图 → 客户产品借用的系统首图 → 系统直选行的系统产品图。
  - 无图时显示占位图标，不报错。
- 点击缩略图（放大镜）弹出全屏图片浮层查看大图，沿用现有图片浏览习惯；勾选/删除等其它操作不变。
- 手机端缩略图用小图（thumbUrl），放大时才加载原图，避免内存问题。
- **编辑已有订单**时，行图片要能回显（通过现有订单行图片接口并入草稿）。

## 4. 功能三：系统产品库直选 + 存入客户产品库

### 从系统产品库添加

- 「填写订单详情」弹窗的产品明细区，在现有客户产品选择器旁增加「**从系统产品库添加**」入口。
- 复用报价单/销售单已有的 `LibraryProductPicker`：带图、按品名/SKU/规格搜索、**只显示在售产品**（停售/草稿不出现）。
- 选中一个系统产品后，新增一行订单明细，自动带入：
  - 品名、SKU、规格、产品图片、系统产品引用（`product_id`）。
  - 装箱数：取该系统产品首条包装的外箱装箱数；无包装则默认 1 待填。
  - **单价默认空/0 待填**（系统产品只有采购成本价，没有统一对外售价，不自动把成本当售价）。
  - 该行 `customer_product_id = null`（尚未关联客户产品）。
- 临时客户和正式客户都能用这个入口。

### 存入客户产品库（订单行按钮）

- 凡是从系统产品库直选、尚未关联客户产品的行，行上出现「**存入客户产品库**」按钮：
  - **仅当选了正式客户时可用**；临时客户下按钮禁用，提示「转正后可存入客户产品库」。
  - 点击后调用现有 `from-library/complete` 接口，把该行信息建为客户产品：
    - 品名/SKU/规格/包装/图片来自系统产品与该行的当前值；
    - 最终价格取该行**当前单价**；运费/箱取该行值。
  - 建成后把订单行的 `customer_product_id` 关联上新客户产品，按钮变为已存入状态。
  - 若该客户已存在相同产品（接口去重），提示已存在，不重复创建。
- 存入是**逐行、手动**触发，不自动批量存。

## 5. 功能四：临时客户转正

- 入口：临时客户订单（`customer_id = null` 且有客户名）的详情/行内展开里，增加「**转正为客户**」按钮。
- 流程：
  1. 点击后打开客户编辑弹窗，**预填该临时名称**，可补联系人、电话、收件信息、开票信息。
  2. 保存时新建正式客户；**若该名称已存在正式客户，则直接挂接到已有客户，不重复建**。
  3. 挂接历史订单：把所有 `customer_id = null` 且 `customer_name` 与该名称一致的订单，`customer_id` 指向这位客户。
  4. **先预览**将挂接的订单数量与单号列表，确认后再执行（不可逆操作先给 dry-run）。
- 挂接后：
  - 这些订单变为正式客户订单，可用客户产品库；订单上的客户名称快照保留不变。
  - 转正**不自动创建客户产品**；需要时再用功能三的行按钮逐行存入。
- 转正只处理订单挂接，不动报价单/销售单（本期范围外）。

## 6. 数据模型与迁移

- **`order_items` 新增 `product_id` 列**（系统产品引用，`REFERENCES products(id) ON DELETE SET NULL`），数据库版本升到 **43**。与报价单/销售单行同构。存量行回填空。
- 订单输入解析、创建/更新订单、订单行类型增加 `productId` 透传与落库。
- **订单行图片解析扩展**（`getOrderItemImages`）：
  - 有客户产品：自有图优先（尊重 `image_cleared`）→ 系统首图。
  - 无客户产品但有 `product_id`：用该系统产品的图片。
- 新增**转正接口**：建/取客户 + 批量挂接同名未挂客户订单，返回挂接结果；挂接前可先查询预览。
- 临时客户名称快照后端已支持，无需新增订单表字段。
- 迁移遵循现有规范：先快照、preflight 校验、事务内执行；状态切换类操作不刷新无关 `updated_at`。

## 7. 本期不做

- 不自动创建「临时客户档案」，临时客户只留在订单名称上。
- 转正不自动建客户产品、不自动改订单行关联（用行按钮手动存）。
- 不改报价单、销售单、备货、发货、箱唛主流程。
- 系统直选行不自动计算对外售价（无统一售价口径，单价手填）。
- 不做临时客户的联系人/电话独立档案（订单收件信息照常填）。

## 8. 验收标准

- 不建客户档案，直接输名字能开单并保存；列表/详情显示名称与「临时」标记。
- 临时客户订单能从系统产品库选品（带图、只在售）、手填行，正常保存与流转。
- 「填写订单详情」弹窗每行有缩略图，点击放大；编辑已有订单图片能回显；手机端不溢出、不闪退。
- 正式客户下，系统直选行能一键存入客户产品库并关联；重复产品有提示；临时客户下按钮禁用且有提示。
- 临时客户订单能转正：预填名称、重名挂已有客户、预览并挂接同名历史订单；转正后可用客户产品库。
- 停售系统产品不出现在直选器；历史订单引用的停售产品图片仍显示。
- 数据库迁移到 43 后，存量订单与图片正常；备份恢复后数据完整。
- 现有订单/报价/销售/备货发货用例回归通过。

## 9. 待确认（默认按下面执行）

1. **转正挂接范围**：默认挂接**所有**同名且未挂客户的订单（含草稿，不分创建人），预览列出单号。若只想挂当前这一单、或只挂自己创建的，请说明。
2. **临时客户重名**：输入的名字若与已有正式客户完全一致，默认引导选已有客户；转正时重名直接挂已有客户。
3. **系统直选行单价**：默认空/0 待填，不自动带采购价或估算售价。若要带某个口径的价格，请指定。
4. **带图范围**：默认只改「填写订单详情」弹窗的行；订单查看页已有图保持。若列表行内展开也要统一调整，请说明。
